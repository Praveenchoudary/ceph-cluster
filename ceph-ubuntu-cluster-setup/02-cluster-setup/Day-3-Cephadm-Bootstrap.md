# Day 3 — Cephadm Bootstrap (Ceph Squid v19.x)

This guide bootstraps the Ceph cluster on the **first node (ceph1)** using `cephadm`.

---

## 3.1 Install cephadm

Run on **ceph1** only:

```bash
apt install -y cephadm
```

Add the Ceph Squid repository and install the `cephadm` package properly:

```bash
sudo ./cephadm add-repo --release squid
sudo ./cephadm install
```

Verify:

```bash
cephadm version
```

---

## 3.2 Bootstrap the Cluster

Run on **ceph1**:

```bash
sudo cephadm bootstrap --mon-ip 192.168.1.11
```

This single command will:

- Create a new Ceph cluster with one Monitor (MON) and one Manager (MGR) on ceph1
- Generate a minimal `ceph.conf` and admin keyring in `/etc/ceph`
- Install the `ceph` CLI as a container alias
- Print the **Dashboard URL, username, and initial password** — save these

Example output:

```
Ceph Dashboard is now available at:

     URL: https://ceph1:8443/
    User: admin
Password: <auto-generated-password>
```

---

## 3.3 Install the ceph CLI Shell Alias

To run `ceph` commands directly on the host (not just inside the container):

```bash
sudo cephadm install ceph-common
```

Verify:

```bash
ceph -v
ceph status
```

Expected output should show `HEALTH_WARN` at this stage (normal — cluster only has 1 MON/OSD so far).

---

## 3.4 Verify Initial Cluster State

```bash
ceph -s
```

You should see something like:

```
  cluster:
    id:     <uuid>
    health: HEALTH_WARN
            OSD count 0 < osd_pool_default_size 3

  services:
    mon: 1 daemons, quorum ceph1
    mgr: 1 daemon(s)
    osd: 0 osds: 0 up, 0 in
```

This is expected — we haven't added ceph2, ceph3, or any OSDs yet.

---

## 3.5 Copy Cluster SSH Key to Other Nodes

`cephadm` uses its own internal SSH key (separate from your manual key in Day 2) to manage remote hosts:

```bash
ceph cephadm get-pub-key > ~/ceph.pub
ssh-copy-id -f -i ~/ceph.pub root@ceph2
ssh-copy-id -f -i ~/ceph.pub root@ceph3
```
